## Context

See proposal.md — Why. Constraints that shape the approach:

- `/opsx:archive` and the `openspec-archive-change` skill are generated by OpenSpec and regenerated by
  `openspec update`; the kit cannot edit them. The kit only steers them through
  `openspec/config.yaml` → `operations.archive.guidance` (returned as `operationGuidance` by
  `openspec instructions archive --json`, advisory only) and through its own skills/doctrine.
- Kit doctrine archives **inside the PR, before the merge** (`core/docs/openspec-tasks-mandatory-steps.md`
  Pre-merge Review, step 11.5). The agent never pushes or merges.
- Verified with OpenSpec 1.9.0 in a scratch repo: `openspec archive -y --json <change>` returns
  `archive.archivedAs` (e.g. `2026-11-06-add-foo`) and moves the folder to `openspec/changes/archive/`;
  after deleting `archive/<folder>/specs/`, `openspec validate --archived` still passes (exit 0).
- Consumer config is `.claude/sdd-harness.env` (project-owned, never overwritten on update), parsed by
  `load_env_safe` in `core/.claude/hooks/lib.sh` with a key allowlist.
- Hooks are bash, dispatched by `core/.claude/hooks/invoke.cjs`, which today forwards only the script
  path (no extra arguments).
- The kit repo has no test infrastructure and must not gain build tools.

## Goals / Non-Goals

**Goals:**
- One bash entry point usable by the skill, by humans and by tests, identical on Git Bash / Linux / macOS.
- Safety by construction: destructive steps gated on a verified archive commit or on Git reachability,
  dry-run available everywhere, folder pruning dry-run unless `--apply`.
- Squash-merge safe by default.

**Non-Goals:**
- A PowerShell twin of the script (Git Bash is already a hard requirement of the hooks).
- Fetching from or pushing to remotes. The script never touches the network.
- Pruning OpenSpec stores (`--store`); only the local `openspec/` root.

## Decisions

### D1. Script + skill, not a hook
`core/.claude/openspec-archive.sh` is installed to `.claude/openspec-archive.sh` (kit-owned) and driven
by a new skill `openspec-archive`. A PostToolUse hook was rejected: hooks must not create commits
(surprising side effects, no user confirmation, runs inside unrelated Bash calls). A skill keeps the
agent in the loop, shows dry-run output and asks before destructive steps.

Subcommands:

| Subcommand | Purpose | Destructive default |
|---|---|---|
| `archive <change> [--dry-run]` | `openspec archive -y --json <change>` then `post-archive` | yes (commits) |
| `post-archive <folder> [--dry-run]` | after `/opsx:archive`: index row → archive commit → prune per mode → threshold notice | yes (commits) |
| `index [--dry-run]` | rebuild / backfill `INDEX.md` (writes file, no commit) | file only |
| `prune-deltas [--dry-run] [--only <folder>]` | deferred prune of deltas already on the default branch | yes |
| `prune-folders [--apply] [--only <folder>]` | threshold folder prune behind snapshot tag | **no** (dry-run unless `--apply`) |
| `config` | print effective configuration | no |

The skill's normal path is `/opsx:archive` (keeps OpenSpec's agent-driven sync prompts) followed by
`post-archive <folder>`. `archive <change>` exists for non-interactive use and tests.

### D2. Ordering and commit guards (archive)
1. Preflight: inside a Git work tree, not detached, no merge/rebase/cherry-pick in progress, and
   `git status --porcelain` shows nothing outside `openspec/` (the paths OpenSpec just touched).
   Failure → no commit, no prune, warning, exit 2.
2. Write/refresh the `INDEX.md` row (reads `proposal.md` and `specs/` while they exist).
3. `git add -A -- openspec/` and `git commit` (hooks run; never `--no-verify`). Commit success is
   checked by comparing `git rev-parse HEAD` before/after, not only the exit code.
4. Only if step 3 produced a new commit → pruning per `KIT_ARCHIVE_PRUNE_DELTAS`.

### D3. Delta prune modes and the squash-merge risk
Archive happens on the PR branch. With `immediate`, commit c (deltas) and commit d (prune) both sit on
the branch; a squash merge produces one commit on the default branch whose tree equals d → the deltas
never exist in default-branch history (only in the hosting platform's PR ref). Hence:

- `deferred` (default): the archive PR carries only commit c. `post-archive` then runs `prune-deltas`,
  which prunes **other** archived changes whose `specs/` is reachable as
  `git cat-file -e <default-branch>:openspec/changes/archive/<folder>/specs`. The proof commit
  recorded in the index is `git log -1 --diff-filter=A --format=%h <default-branch> -- <path>/specs`.
  Works for squash, merge commit and rebase. Pruning lags one archive behind.
- `immediate`: c then d on the branch; only correct for merge-commit or rebase-merge repos. Documented
  as such in CONFIG; the skill prints a reminder when it is set.
- `off`: commit c only.

The default branch ref is `KIT_ARCHIVE_DEFAULT_BRANCH` or the target of `refs/remotes/origin/HEAD`, else
`main`. The script never fetches; a stale remote-tracking ref only delays pruning (safe direction). The
skill suggests `git fetch` to the human when nothing is eligible.

### D4. INDEX.md format
```
# Archived OpenSpec changes

<!-- Generated by .claude/openspec-archive.sh. Edit rows only to fix titles. -->

| Folder | Title | Capabilities | Archive commit | Snapshot tag |
|---|---|---|---|---|
| 2026-11-06-add-foo | Add foo | foo | 1a2b3c4 | — |
```
Rows are keyed by folder; existing rows are preserved (pruned folders stay listed), cells are updated
only when new information exists (commit `pending` → hash, tag `—` → tag). Output is regenerated
deterministically and written only if bytes differ (idempotence). Pipes in titles are escaped.

### D5. Folder pruning
Eligible = not among the newest `KEEP` folders (by name, which is date-prefixed) AND date prefix older
than `MAX_AGE_DAYS`. Date arithmetic uses `date -d` (GNU, Git Bash) with a `date -j -f` fallback (BSD).
With `--apply`: create annotated tag on HEAD (`git tag -a <name> -m "OpenSpec archive snapshot before
pruning N folders"`), reuse if same name already on HEAD, else first free `-N` suffix; then
`git rm -r` the folders, update INDEX rows, one commit. Prints a boxed "TAG IS LOCAL ONLY" warning with
`git push origin <tag>`.

### D6. Configuration
Add `KIT_ARCHIVE_*` keys to the `load_env_safe` allowlist and defaults in `lib.sh`; validate values in
the script (invalid → safe fallback + warning). Add the keys with comments to `adapters/_template.env`
and every stack `.env`. Installer follow-up warning lists missing keys (same grep pattern as 1.5.1).

### D7. Windows dispatch
Extend `invoke.cjs` to forward `process.argv.slice(3)` to the script (backward compatible: hooks pass
none). The skill runs `node .claude/hooks/invoke.cjs .claude/openspec-archive.sh <subcommand> …` so
Windows never hits WSL bash.

### D8. Context hygiene
- `session-context.sh`: pending-task grep excludes `archive/`.
- `openspec-implement`: list active changes with a command that excludes `archive`.
- `settings.json`: `permissions.deny` += `Read(openspec/changes/archive/*/**)` (INDEX.md stays readable).
  The exact path-pattern semantics are checked against current Claude Code permission docs during
  implementation; if `Read` deny does not cover Grep/Glob, instructions remain the main control.
- Skills `adversarial-review`, `explain`, rules `00-core`, `20-openspec`, `copilot-instructions.md`,
  `base-standards.md`: "history = `openspec/changes/archive/INDEX.md` + `git log` / `git show`; do not
  read archived folders unless the human asks".

### D9. Tests
`tests/openspec-archive.test.sh` in the kit repo (not payload): plain bash, `mktemp -d` Git repos,
real `openspec` CLI (skips with a clear message if absent), a bare repo as fake remote, and a
squash-merge simulation (`git merge --squash` + commit on the default branch). One test function per
spec scenario, named after it. No framework, no build step.

### D10. Kit repo governance
`openspec init --tools none` in the kit root (no `.claude/` or `.cursor/` generated, avoiding confusion
with `core/` payload). `AGENTS.md` / `CLAUDE.md` §1–2 updated in lockstep.

## Risks / Trade-offs

- [Deferred pruning lags one archive behind] → acceptable; `prune-deltas` can be run at any time.
- [Stale `origin/HEAD` ref] → only delays pruning; skill suggests `git fetch`.
- [First archive after updating a legacy repo prunes many deltas at once] → dry-run listing shown by
  the skill first, one dedicated prune commit, `--only` to narrow.
- [Snapshot tag only local] → loud warning + exact push command; never auto-pushed.
- [`Read` deny may not cover every search tool] → instructions and hook exclusions are the primary control.
- [Repos that edit `INDEX.md` by hand] → rows are preserved; only empty/pending cells are updated.
- [Commit hooks in consumer repos (lint, docs-gate)] → run normally; on failure nothing is pruned.

## Migration Plan

1. Release as 1.6.0. Consumers re-run the installer; kit-owned files arrive, project-owned files stay.
2. Installer warns about missing `KIT_ARCHIVE_*` keys and the archive guidance line in
   `openspec/config.yaml`; defaults apply meanwhile.
3. Rollback: set `KIT_ARCHIVE_PRUNE_DELTAS=off` and `KIT_ARCHIVE_INDEX=0`; pruned content is
   recoverable from the recorded commits and tags.
